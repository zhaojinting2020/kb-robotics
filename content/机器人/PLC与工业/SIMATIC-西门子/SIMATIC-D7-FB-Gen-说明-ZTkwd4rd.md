# Introduction

使用 SIMATIC D7 功能块生成器，您可以为 D7-SYS 配置工具生成用户自定义的功能块，并将其组合成一个库。

### 注意

要生成此类功能块，您需要使用能够生成与 R3000/R4000 兼容的目标代码的程序。在安装 D7 功能块生成器之后，请勿移动或卸载这些程序。

## Block Notation

### Overview

功能块（FB）是根据定义文件生成的。这些定义文件将通过 D7 功能块生成器转换为目标代码和显示模板（Mask）。一个名为 `<name>` 的功能块由以下三个文件定义：

- `<name>.dat`：包含功能块的输入/输出（I/O）和 CFC（连续功能图）信息
- `<name>.c`：功能块的运行代码（以 C 源码形式）
- `<name>.bmp`：功能块的内部图形表示

本文件首先介绍功能块的概念及其输入/输出结构，并说明名称格式及其在文件命名和定义文件中的使用方式。随后将详细说明功能块 I/O 和 CFC 信息的格式，包括用于描述这些信息的文件组成结构，以及其中必须项和可选项的具体内容。文档还解释了功能块必须具备可重入性（re-entrant）的原因，并说明为实现此特性，功能块运行代码所需满足的前提条件。同时，还将展示如何在功能块的主函数, 局部函数及与外部模块关联的函数中访问功能块的 I/O 和局部变量。头文件 `p32.h` 定义了功能块所需的常量, 宏和函数原型。文档还将说明该头文件的内容及其宏（例如用于数值转换）的使用方式。

### Function Block Names

对功能块（FB）定义文件的命名规则做出了一些基本规定：

- **功能块名称（FB name）**：  

 FB 名称由 1 至 6 个字符组成。
- **文件命名**：  

 定义文件, 包含文件, 临时文件, 产出文件等的文件名必须以 FB 名称开头，且必须使用小写字母。
- **定义文件中的 FB 名称**：  

 在定义文件中，FB 名称必须使用大写字母。
- **注释中的 FB 名称**：  

 在注释中，FB 名称的大小写格式不做强制要求，可以自由使用大写或小写字母。

#### I/O and CFC Information

功能块 `<name>` 及其输入/输出（I/O）和局部变量在定义文件 `<name>.dat` 中进行定义。该定义文件由多个子块组成，具体规则如下：

一般规则：

- **定义范围**：  

 所有需定义的功能块数据必须位于关键字 `FUNCTION_BLOCK` 与 `END_FUNCTION_BLOCK` 之间。在 `FUNCTION_BLOCK` 前只允许出现注释。  
`END_FUNCTION_BLOCK` 后可以添加任意内容，但这些内容将被忽略。
- **关键字使用**：  

 每一项定义通常以关键字（如 `COMMENT`）开头，且必须为大写字母。  
**例外情况**：输入/输出（连接口）和局部变量的描述不以关键字开头，而是以其名称（标识符）起始。
- **替换项 `< >`**：  

 尖括号 `< >` 中的内容需替换为合法的实际值（包括尖括号本身）。
- **可选项 `{ }`**：  

 大括号 `{ }` 中的数据为可选。可以省略其中某项或全部内容。只有在括号中所有内容都被省略时，括号本身才可以省略。
- **默认值**：  

 若可选项被省略，系统通常会使用默认值进行替代。
- **空白字符**：  

 空格, 水平制表符（Tab）, 换行符等可用于结构化数据，但**关键字, 名称, 多位数字等中不能出现空白字符**。
- **注释格式**：  

 注释可使用 `/* ... */` 或 `//`（直至行尾）两种格式，且可出现在允许空白字符的位置。
- **无变量时的处理**：  

 若功能块不包含输入/输出或局部变量，相应的数据块（例如包含 `VAR_INPUT`, `VAR_OUTPUT` 或 `VAR` 的块及 `END_VAR`）应**完全省略**，**不作替代**。
- **格式要求**：  

 所有数据可不依赖固定格式书写。但为提高可读性，推荐每行仅定义一项。
- **字符序列书写**：  

 所有需要输入的字符或字符序列必须用单引号 `'` 包裹。
- **转义规则**：  

 若字符序列中包含单引号 `'`，需在其前添加 `$`（例如 `'$''`），以避免被误认为是字符串结束标志。若字符序列中包含 `$`，则需写作 `$$`。
- **字符替换**：  

 字符串中若出现制表符或换行符，生成代码时将其替换为一个空格。随后将介绍定义文件 `<name>.dat` 的语法结构。文件的模块头部分对功能块生成器无实际意义，此处仅作简略说明。

```text
/*
; Format of a definition file, I/O and CFC information 
; Module header
*/

FUNCTION_BLOCK
 {<optional block header parameter>};
 NAME_FB:<block type name>;
 RUNTIME:<computation time of the block in 1/10 microseconds on PM5>;
VAR_INPUT
 <description of the inputs>
END_VAR
VAR_OUTPUT
 <description of the outputs>
END_VAR
VAR
 <description of the local variables>
END_VAR
END_FUNCTION_BLOCK
```

#### Description of an input and output

输入/输出参数的描述格式：

`<输入或输出的名称> {<I/O描述的可选参数>} : <数据类型> := <默认值>;`

默认值初始化是可选的。若不需要设置默认值，**需完整省略** `:=<默认值>` 这一部分字符序列。局部变量的描述格式：

`<局部变量名称> : <数据类型>;`

可选参数的数据结构格式：

`<关键字> := <值>;`

以上结构用于定义功能块中输入/输出接口, 局部变量及其可选属性，遵循统一, 规范的格式，便于后续自动生成代码。

#### Length and character scope of the values for obligatory key words

### NAME_FB：功能块类型名称

**长度要求**：1 到 6 个字符

**允许字符**：

第一个字符：必须为大写字母 `[A–Z]`

后续字符：可以是大写字母 `[A–Z]`, 数字 `[0–9]` 或下划线 `_`

---

### RUNTIME：功能块的计算时间

表示在 PM5 / T400 处理器上运行该功能块所需的时间，单位为 **1/10 微秒**

**长度要求**：1 到 4 个数字字符

**允许字符**：仅数字 `[0–9]`

---

### 输入 / 输出 或 局部变量的标识符（名称）

**长度要求**：1 到 3 个字符

**允许字符**：

第一个字符：必须为大写字母 `[A–Z]`

后续字符：可以是大写字母 `[A–Z]`, 数字 `[0–9]` 或下划线 `_`

---

这些规则确保了命名规范, 简洁，便于在自动化工程工具中处理和识别。

#### Key words for optional data

### 空字符串（Empty string）

表示为两个连续的单引号 `''`，中间**无空格**。用于在字符串中表示一个空格。

---

### String 类型定义

**String_1**：长度为 1 的字符串，可包含以下字符：  
`[0–9]`, `[A–Z]`, `[a–z]`, `' '`（用两个单引号表示的空格）或空字符串。

**String_8**：最多 8 个任意字符。

**String_80**：最多 80 个任意字符。

---

### 多语言支持的关键字语法

以下关键字可使用多语言重复定义，每种语言对应一条记录：

`COMMENT <language ID> := String_80;`  
`FAMILY  <language ID> := String_8;`

---

### 语言 ID（language ID）说明

可取以下形式：

`0 个或多个空格` → 代表默认语言

`两个小写字母` → 表示具体语言 ID（如 `gr`, `us`）

**语言 ID 的规则检查**：  
 系统仅检查是否为“0 到 n 个空格”或“正好两个小写字母”。不会进行进一步语义验证。

**语言 ID 的作用**：  
 被写入功能块的图形模板及中间结构中，由 **CFC 编辑器**进行解释与使用。

---

### CFC 编辑器支持的语言 ID 示例

`gr` → 德语（German）

`us` → 英语（English）

---

这些规则允许在定义文件中添加多语言注释和族名，以支持国际化配置和图形显示。

| BYTE | 8 位字节序列 | *char | 0 |
| INT | 16 位整数 | *int16 | 0 |
| WORD | 16 位字序列 | *int16 | 0 |

 D7 功能块生成器会检查用户指定的默认值是否与对应 I/O 的数据类型兼容。

 用户必须为 SDTIME 类型提供带单位的默认值，例如 `5.0ms`（表示毫秒）。
- **STRING 类型限制**：  

`STRING` 类型**仅允许用于输入端口（Input）**，**不适用于输出或局部变量**。

---

  - **不允许**设置可选参数（optional component）；
  - **不支持**默认值定义；

 当你在定义文件中使用 `UINT` 类型时，系统会自动在头文件中生成 `u_int16` 类型定义，并为其分配一个 16 位内存空间。但该内存空间**不会被预设初值**。

| 数据类型 | 含义 | 取值范围 | 示例写法 |
| --- | --- | --- | --- |

⚙️ 数值基数说明（用于整数类型）：

对于 `BYTE`, `INT`, `WORD`, `DINT`, `DWORD` 这些整数类型，可以指定数值的**进制**：

`2#` → 二进制（如：`2#1010`）

`10#` → 十进制（如：`10#255`）

`16#` → 十六进制（如：`16#FF`）

> 如果未指定进制：
> 
> `BYTE`, `WORD`, `DWORD` 默认按 **十六进制** 解析；
> 
> `INT`, `DINT` 默认按 **十进制** 解析。

---

🧮 关于浮点数（`REAL`, `SDTIME`）的精度：

这些类型允许保存 **非规格化（denormalized）数值**，范围大致为 `±1.1755e-38`。但非规格化数值的精度较低，因为其尾数（mantissa）左侧会用零填充，降低有效位数。

### FB run code

功能块的运行代码以 C 程序形式写入 `<name>.c` 文件中。适用于功能块运行代码定义文件的规则如下：

- 模块标识通过 `FBTNAM(<name>)` 扩展，其中名称以字符序列 `FBTNAM` 开始，并以功能块名称后的括号结束。
- 为了简化功能块编写，功能块的主函数（即系统运行后进行周期处理的常规模式）与初始化模式（系统在复位或上电后启动时）不采用通常的 C 语言函数头，而是使用以下“符号化”函数头：

  - `NRM()`
  - `INI()`
- D7 功能块生成器将基于此生成包含所需传参的函数头。功能块生成器运行时遵循以下规则：

- 文件开始至模块名称之前的所有行将被忽略。
- 功能块生成器读取并解析名称。
- 模块名称之后至文件末尾的所有行均被视为运行代码。运行代码可包含多个函数：包括可由操作系统直接调用的主函数 `NRM()` 和 `INI()`，以及由主函数直接或间接调用的附加函数。附加函数必须完整定义，即包括函数名称和传参声明，并应位于主函数之后。每个附加函数在首次定义函数（通常为 `NRM()`）之前必须声明原型，以便于程序阅读者获取包含参数的函数列表。

**注意：** 所有局部功能块附加函数及其原型必须声明为 `static`。

```java
// 函数原型声明（必须 static）
static int helper_func(int a);

// 主函数
NRM()
{// 正常运行逻辑
}
INI()
{// 初始化逻辑
}

// 附加函数定义
static int helper_func(int a)
{return a + 1;
}
```

#### Definition of functions

一个功能块（FB）及其所有函数必须具备**可重入性**（re-entrant）。为实现这一点，必须遵守以下规则：

---

### ● 功能块内部接口中不得声明变量

如果在功能块的内部接口中（即在所有函数之外）声明变量，那么这些变量将被赋予 `extern` 内存类别，或者（根据具体数据）为 `static`。此类变量在 SIMATIC TDC / SIMADYN D 系统的整个运行期间只会为该模块（即功能块）分配一次内存，这将导致该功能块不具备可重入性。因此，各个函数之间**不得通过公共可见区域的变量**来进行数据传递，应通过**调用参数和函数返回值**进行传递。若某些数据是在功能块运行过程中生成的，并且需要在后续运行中保持不变，则应使用\*\*局部变量（local variables）\*\*来保存。

---

### ● 功能块函数中不得使用 static 变量

在“变量（堆栈变量）”项下，每个函数需定义其专用变量，这些变量必须属于 `auto` 或 `register` 内存类别。出于上述原因，**不得在功能块的函数中使用 `static` 内存类别的变量**。解释：

🧠 首先，什么是“可重入性”（Reentrant）？

\*\*可重入函数（reentrant function）\*\*是指：

> **在任意时间点被多个任务同时调用时，能正确运行，互不干扰的函数**。常见于多任务系统, 实时系统中，比如 PLC 或嵌入式控制系统。如果一个功能块不是可重入的，那它在多个任务或周期中同时被调用时可能会**数据错乱或互相覆盖**。

---

💣 为什么在功能块外面声明变量会破坏可重入性？

来看例子 ↓

```text
$int counter = 0;  // 这是“模块级”的变量$

void myFunction() {
    counter++;  // 多个调用共享同一个 counter
}
```

这个 `counter` 变量 **只分配一份内存**，对所有调用共享。这意味着多个任务, 多个周期调用时，都会改动这一个 `counter`，就会互相干扰。

---

💣 在功能块中声明的变量为什么是 `extern` 或 `static`？

情况1：模块外声明但未初始化

```text
int value; // 没有初始化，会被视作 `extern`（外部变量）
```

这意味着变量的内存定义在别的地方，只是引用。在编译器或链接阶段，会被视为一个**全局共享的内存**。情况2：模块内声明 + 初始化

```text
$int value = 5; // 有初始化，会变成 `static`$
```

编译器会分配一个固定的内存区域。生命周期是**整个程序运行期间**。所以也被多个调用共享。所以说，不管是 `extern` 还是 `static`，**都是全局唯一的一份数据**，不属于某个调用上下文。这就跟“你们几个人共用一个水杯”一样，不会互不影响。

---

✅ 正确做法：用局部变量

```text
void myFunction() {int counter = 0;  // 这是局部变量，每次调用都有一份独立副本
    counter++;
}
```

这种变量位于栈上（stack），属于当前函数调用，任务之间互不干扰。这才是**可重入函数的关键条件**。

#### External functions

功能块（FB）的编写者可以定义或使用**外部函数**，这些函数不集成在功能块的代码中，而是位于独立的 C 文件中。为了使功能块库能够使用这些外部函数，必须遵守以下规定：

- **在单独的 C 文件中实现外部函数。**
- **在头文件中定义外部函数的函数原型。**
- **在使用该外部函数的每个功能块文件中，通过 `#include` 指令引入头文件。**
- **在包含了头文件的功能块文件之后，通过 `#include` 指令引入外部函数所在的 C 文件。**

#### Accessing I/O from the main functions of an FB

功能块（FB）的编写者应当能够**以尽可能简洁的方式访问输入/输出（I/O）和局部变量**。为实现这一目的，在每次生成功能块期间，系统会自动创建一个包含文件 `<name>_i.h`，并将其包含进功能块中。在该头文件中，系统为每一个 I/O 和局部变量的标识符保存了一条 `#define` 指令。通过这些宏定义，程序员在运行代码中只需使用相应的标识符即可访问对应的值。因此，在运行代码中，**I/O 和变量标识符仅可用于访问 I/O 或局部变量**。

---

除了 `STRING` 类型和 `GLOBAL` 类型外，**变量标识符本身就足以用于访问其对应的值**。
