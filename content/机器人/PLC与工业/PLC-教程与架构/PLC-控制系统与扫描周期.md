# PLC 控制系统与扫描周期

PLC 是连接现场设备与工艺控制逻辑的实时控制器。它的价值不只在于“运行程序”，而在于以可预测的周期完成采集、计算、输出和诊断，并让工程师能够安全地修改、验证和维护系统。

## 系统位置与边界

典型链路是“传感器/执行器 → I/O 与驱动 → PLC → HMI/SCADA/工程站”。PLC 负责确定性的控制闭环；HMI 负责操作与可视化；SCADA 负责监控、归档和调度；工程站负责组态、下载与诊断。不要把上位机的非实时任务放入控制周期，也不要假定 PLC 的每个网络服务都具备硬实时特性。

## 硬件与过程映像

PLC 的基本组成包括 CPU、存储器、电源、通信接口和本地/远程 I/O。程序一般不直接操作物理端子，而是读写过程映像：输入刷新后形成输入映像，逻辑基于该快照计算，输出映像在周期末统一写到现场。

这带来两个工程结论：一是同一周期内的输入通常保持一致；二是短于扫描周期的脉冲可能被漏采。对快速事件应使用中断、高速计数或专用通信/驱动能力，并明确其优先级和数据交接方式。

## 扫描周期与实时性

最常见的执行模型是：输入采样 → 按任务顺序执行程序 → 输出刷新 → 后台通信和诊断。周期上限必须小于工艺允许的响应时间，并预留通信、诊断和峰值执行时间。周期抖动往往来自任务竞争、阻塞 I/O、过大的循环、在线调试或共享数据争用。

设计时应先定义每类任务的周期、最坏执行时间和失效后的安全状态；再以测量数据验证，而非只以“平均扫描时间”判断。

## 启停与安全

冷启动、热启动、程序下载和掉电恢复会改变变量和输出的初始状态。工程应明确：保持变量的范围、输出使能条件、通信失联策略、急停与硬件联锁的职责。安全功能不能仅依赖普通程序逻辑；其实现、验证与变更控制应符合项目的安全要求。

## 设计检查表

- 每个信号是否定义了量程、单位、刷新来源和失效值？
- 每个周期任务是否有预算和超时监测？
- 快速事件是否避免了普通扫描遗漏？
- 下载、重启、断网后输出是否回到可接受状态？
